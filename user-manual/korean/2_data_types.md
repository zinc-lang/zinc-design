
# 기본 데이터 타입

명명 규칙: 모든 이름이 있는 타입의 타입 이름은 대낙타 표기법 UpperCamelCase입니다. (`fn` 키워드는 예외입니다. 이 키워드는 주로 함수 정의 장면에서 쓰이기 때문입니다.)

## Bool 타입

`Bool` 타입에는 두 가지 가능한 값이 있습니다. `true`와 `false`입니다.

`Bool` 타입의 부정은 `!` 연산자를 사용합니다.

## 정수

|  길이 |  부호 있음  |  부호 없음  |
|-------|---------|----------|
| 8 bit | Int8      |  UInt8      |
| 16 bit | Int16      |  UInt16      |
| 32 bit | Int32      |  UInt32      |
| 64 bit | Int64      |  UInt64      |
| arch-dependent | Int      |  UInt  |
| arch-dependent | Short    | UShort  |

Int/UInt 타입의 크기는 대상 플랫폼에 따라 다릅니다. 64비트 플랫폼에서는 64 bit 크기이고, 32비트 플랫폼에서는 32 bit 크기입니다. C 언어의 `intptr_t` / `uintptr_t`와 동등합니다.
Short/UShort 타입의 크기는 대상 플랫폼에 따라 다르며, 항상 Int/UInt 타입의 절반입니다. 64비트 플랫폼에서는 32 bit 크기이고, 32비트 플랫폼에서는 16 bit 크기입니다.


정수 리터럴은 `_`를 구분자로 쓸 수 있습니다.

접두사로 진법을 구분할 수 있습니다. `0o`는 8진수, `0x`는 16진수, `0b`는 2진수를 나타냅니다.

정수 리터럴은 접미사 타입을 허용합니다. 접미사 타입은 소문자입니다. 예: `123_i8`  `100_i`  `0x64_u`.
다른 컨텍스트 정보가 없으면 정수 리터럴의 타입을 추론할 수 없습니다. 사용자에게 정수 리터럴에 타입 접미사를 붙여 타입을 명시하기를 권합니다.

정수 산술 연산에서 오버플로가 발생하면 항상 wrapping 모드입니다. 다른 동작이 필요하면 표준 라이브러리를 호출하십시오. 표준 라이브러리는 정수에 `checked_add` 등 멤버 함수를 제공합니다(아직 구현되지 않음).

zinc는 "비트 연산" 연산자를 제공하지 않습니다. 왼쪽 시프트, 오른쪽 시프트, 비트 AND, 비트 OR, 비트 NOT, 비트 XOR을 포함합니다.
대신 표준 라이브러리에서 정수 타입에 멤버 함수로 비트 연산을 제공합니다. 예를 들어 `bit_and`는 기능 요구를 충분히 충족합니다.

이유: 비트 연산의 사용 빈도가 낮고 정수 타입에만 적용되므로, 전용 연산자를 설계하는 것은 다소 낭비입니다.
게다가 비트 연산은 원래 위 기능만이 아니라 rotate, reverse, count_ones 등 잘 쓰이지 않는 열여 가지 비트 연산 기능도 있습니다. 이들도 원래 멤버 함수로만 제공할 수 있습니다. 개인적으로는 모든 비트 연산 기능을 멤버 함수로 제공하는 편이 더 일관된다고 느낍니다.
ASCII 코드의 기호는 원래 그리 충분하지 않으므로, 이런 기호는 더 중요한 기능에 남겨 두는 것이 더 합리적입니다.


## 부동소수점

부동소수점은 `F32`와 `F64` 타입으로 나뉩니다.

부동소수점 리터럴은 `_`를 구분자로 쓸 수 있습니다.
부동 리터럴은 접미사 타입을 허용하며, 각각 `f32`와 `f64`입니다.

부동 리터럴은 소수점 앞의 0을 생략할 수 없습니다. `.123` 또는 `-.1`은 모두 오류입니다.

## 문자 타입 Char

`Char` 타입은 32 bit이며, 하나의 unicode code point를 나타냅니다.

`Char` 리터럴은 작은따옴표로 둘러쌉니다. 예: `'好'`.

`Char` 리터럴은 이스케이프를 허용합니다. `'\u{3456}'`.

Byte 리터럴을 지원합니다. `b'a'`. Byte 리터럴의 값은 ascii 문자만 가능하며, 타입은 `UInt8`입니다.

표준 라이브러리에 타입 별칭 정의 `type Byte = UInt8;`가 있습니다.

## 배열

배열 안의 원소는 모두 같은 타입입니다. 배열의 길이는 반드시 컴파일 타임 상수여야 합니다.

원소가 `T` 타입이고 길이가 `N`인 배열 타입은 `[T; N]`으로 나타냅니다. 배열은 값 타입이며, 배열 타입은 대입, 인자 전달, 반환 시 모든 원소를 복사합니다.

예시는 다음과 같습니다:

```rust
fn main() {
    let x: [Int; 3] = [1, 2, 3];
}
```

배열 리터럴에는 두 가지 표현 형식이 있습니다:

1. 대괄호 안에 모든 원소를 쉼표로 구분해 직접 나열합니다.

    `[1, 2, 3]`

2. 대괄호 안에 원소와 개수를 세미콜론으로 구분해, 여러 개의 반복 원소를 나타냅니다.

    `[1; 3]`

배열 원소 접근은 인덱스 표현식을 사용하며, 범위를 벗어나면 panic이 발생합니다. 예시는 다음과 같습니다:

```rust
fn main() {
    let mut x: [Int; 3] = [1, 2, 3];
    x[1] = 10;
    println(x[5]); // 컴파일은 통과하고, 실행 단계에서 panic 발생
}
```

## 슬라이스

배열 슬라이스는 배열의 일부를 가리키는 빌림 포인터입니다. 배열 슬라이스는 두 가지입니다. `Slice<'a, T>`와 `SliceMut<'a, T>`이며, 각각 읽기 전용 권한과 읽기·쓰기 권한을 나타냅니다.

```rust
fn main() {
    let x: [Int; 3] = [1, 2, 3];
    let s: Slice<Int> = &x;
    println(s.len());
    println(s[1]);
}
```

배열 슬라이스는 수명을 가진 구조체로, 추가 메타데이터를 가진 빌림 포인터로 볼 수 있습니다. 위 예의 `s` 변수는 두 포인터 크기이며, 각각 시작 주소와 길이를 저장합니다.

주: rust의 `&[T]` 문법을 쓰지 않는 이유는 타입 시스템과 구현 난이도를 단순화하고 싶기 때문입니다.
rust에서 `[T]`는 합법적인 타입이며 독립적으로 쓸 수 있고 dyn sized입니다. 이는 타입 시스템에 일종의 특례를 가져와, 제네릭을 구현할 때 매우 번거롭습니다. zinc는 사용자가 `&[T]/&mut [T]` 타입만 쓰기를 바라며, 단독 dyn sized인 `[T]` 타입도 없고 `Box<[T]>` `Rc<[T]>` 등의 타입도 없습니다.
따라서 `&[T]/&mut[T]` 문법을 바꾸고, 표준 라이브러리에 `Slice/SliceMut` 타입만 제공합니다. 그 의미론은 rust에서 `[T]`를 반드시 빌림 포인터와 합쳐 쓰도록 강제하는 것과 같습니다. Zinc의 `Slice<'a, T>`는 Rust의 `&'a [T]`와 동등합니다.

## 문자열

문자열은 두 가지 타입으로 나뉩니다. `Str`과 `String`입니다.

`Str`은 표준 라이브러리에 정의된 수명을 가진 구조체 `struct Str<'a>`입니다. `String` 타입은 표준 라이브러리에 정의된, `Vec<UInt8>` 타입에 기반해 구현된, 수명이 없는 구조체입니다.

문자열 리터럴은 `Str<'static>` 타입입니다.

주: 배열 슬라이스와 마찬가지로 rust의 `str` 키워드를 쓰지 않는 이유는 타입 시스템과 구현 난이도를 단순화하고 싶기 때문입니다.
rust에서 `str`은 합법적인 타입이며 독립적으로 쓸 수 있고 dyn sized입니다. 이는 타입 시스템에 일종의 특례를 가져와, 제네릭을 구현할 때 매우 번거롭습니다. zinc는 사용자가 `&str` 타입만 쓰기를 바라며, 단독 dyn sized인 `str` 타입도 없고 `Box<str>` `Rc<str>` 등의 타입도 없습니다.
따라서 `str` 키워드를 바꾸고, 표준 라이브러리에 `Str` 타입만 제공합니다. 그 의미론은 rust에서 `str`을 반드시 읽기 전용 빌림 포인터와 합쳐 쓰도록 강제하는 것과 같습니다. Zinc의 `Str<'a>`는 Rust의 `&'a str`과 동등합니다.

문자열 내부는 utf8 인코딩입니다.

C++의 사고로 이해하면, zinc의 `String`은 C++의 `std::string`에 해당하며, 다만 내부 구현에 copy-on-write 메커니즘을 썼습니다. zinc의 `Str`은 C++의 `std::string_view`에 해당하며, 컴파일 타임 수명 검사가 추가로 붙습니다.

문자열 리터럴은 이스케이프를 지원합니다.

## 튜플 tuple

원소가 0개인 튜플을 유닛 타입 unit type이라고 합니다. 유닛 타입은 `()`로 나타냅니다. 빈 튜플 `()` 표현식의 타입이 바로 유닛 타입입니다.
함수 반환 타입을 생략하면, 그 함수가 반환하는 것이 `()` 타입임을 나타냅니다.

원소가 1개인 튜플은 추가로 쉼표로 끝나야 합니다. 그렇지 않으면 컴파일러가 “소괄호 표현식”으로 판정하고 튜플로 보지 않습니다. `(1,)`은 튜플이고 `(1)`은 아닙니다.

원소가 2개 이상인 튜플에서 원소는 서로 다른 타입일 수 있습니다.

## 구조체 struct

`struct` 키워드로 구조체를 정의합니다. 예시는 다음과 같습니다:

```rust
struct User {
    active: Bool,
    username: String,
    email: String,
}
```

구조체는 제네릭을 지원합니다.
구조체 자체와 구조체 멤버 모두 pub으로 수식할 수 있습니다.
구조체는 중괄호 안에 멤버가 없어도 됩니다.

구조체 멤버는 기본값을 지원하며, 기본값은 반드시 상수 표현식이어야 합니다.
```rust
struct User {
    active: Bool = true, // 기본값
    username: String = f"",
    email: String = f"",
}
```

구조체 초기화 표현식은 C 언어와 비슷합니다:

```rust
let user: User = {  // 변수 바인딩의 타입을 주석해 구조체 초기화 표현식의 타입을 지정
    .active = false,
    .username = "John".to_string(),
    .email = "john@gmail.com".to_string(),
};
// 또는
let user = {  // 타입 접미사로 구조체 초기화 표현식의 타입을 지정
    .active = false,
    .username = "John".to_string(),
    .email = "john@gmail.com".to_string(),
} : User;
```

구조체는 C 언어처럼 멤버를 순서대로 익명 초기화하는 것을 지원하지 않습니다:
```
let user: User = { false, "John".to_string(), "john@gmail.com".to_string() };  // 오류
```

기본값이 있는 멤버는 명시적으로 초기화하지 않아도 됩니다.

다른 구조체로 또 다른 구조체를 초기화하는 것을 지원합니다. 여기서는 rust의 점 두 개 `..`가 아니라 점 세 개 `...`를 사용합니다.
zinc에서는 통일해서 점 세 개 `...`로 생략 부호를 나타냅니다. 생략 부호 문법은 여러 장면에서 쓰입니다. 생략 부호 뒤에는 표현식을 붙일 수도 있고 붙이지 않을 수도 있습니다.

```rust
// active는 쓰지 않아도 되며, 기본값을 쓴다는 뜻
let user1: User = { .username = "smith".to_string(), .email = String::new() };

// user1로 user2를 초기화하되, active 멤버의 값만 바뀜
let user2: User = { .active = true, ...user1 }; 

// User 타입 정의의 기본값으로 user3을 초기화하되, active 멤버의 값만 바뀜
let user3: User = { .active = true, ... }; 

// 이는 User 타입 정의 시의 기본값을 전부 사용해 초기화하는 것과 같음.
// 생략 부호가 필요하며, 그렇지 않으면 어휘 분석이 빈 구조체 초기화와 빈 문장 블록을 구분할 수 없음
let user4: User = { ... }; 
```

구조체는 상속을 지원하지 않습니다. zinc는 trait 상속과 `reuse` 메커니즘으로 객체지향 프로그래밍 패러다임을 지원할 예정입니다.

zinc는 tuple struct, 즉 멤버 변수에 이름이 없는 구조체를 지원할 계획이 없습니다. 간단한 구조체에 대해서는 대응하는 snake_case 이름의 전역 함수를 “생성자”로 따로 제공하기를 권합니다.
이렇게 하면 언어 규칙이 비교적 간결하고 통일되며, 사용 관점에서도 명명 규칙이 비교적 통일됩니다. 대문자로 시작하는 “함수처럼 보이는” 것이 나타나지 않습니다.
예:

```rust
struct Weight {
    w: UInt32
}

fn weight(w: UInt32) -> Weight {
    return { .w = w };
}

fn main() {
    // 정의하는 쪽은 조금 번거롭지만, 사용하는 쪽은 기본적으로 tuple struct와 차이가 없음
    let w = weight(1); 
}
```

zinc는 “유닛 구조체”를 지원합니다. 멤버 변수가 없는 구조체는 세미콜론으로 끝낼 수도 있고, 중괄호 안이 비어 있을 수도 있습니다:
```rust
// 다음 두 가지 표기는 같음
struct Unit{} 
struct Unit;
```
하지만 주의할 점은, 유닛 구조체 초기화는 여전히 중괄호가 필요합니다:
```
let x: Unit = { ... };
```

## 열거체 enum

열거체는 `enum` 키워드로 정의합니다:

```rust
enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let k: IpAddrKind = IpAddrKind::V4;
}
```

열거체 멤버는 연관 값을 지원합니다.
```rust
enum IpAddr {
    V4(Byte, Byte, Byte, Byte),
    V6(String),
}
```

중괄호 연관 값은 지원하지 않습니다. 사용자가 매개변수 이름이 필요하면, 모든 매개변수를 구조체로 한 번 감싸기를 권합니다. 효과는 같습니다:

```rust
enum E {
    A{ x:Byte, y: String } // 오류
}
// 대체 표기:
struct EA {
    x: Byte,
    y: String,
}
enum E {
    A(EA),
}
```

열거체 멤버 오버로드를 지원하며, 규칙은 함수 오버로드와 같고, 매개변수 개수가 다른 오버로드만 지원합니다.

```rust
enum Arg {
    Integer(UInt),
    Integer(UInt, UInt),
    Integer(UInt, UInt, UInt),
    Float(F64),
    Float(F64, F64),
    Float(F64, F64, F64),
}
```

enum의 본질은 태그가 있는 공용체(tagged union)입니다. 사용자 정의 enum이 tag가 어떤 정수 타입인지, 그리고 각 멤버에 대응하는 태그 값을 지정하는 것을 허용합니다.
태그 값은 반드시 상수 표현식이어야 하고, 값은 반드시 대응하는 정수로 표현할 수 있어야 하며, 각 멤버에 대응하는 태그 값은 중복될 수 없습니다.

연관 값이 없는 enum만 tag 값을 지정할 수 있습니다.

```rust
enum IpAddr : UInt8 {
    V4 = 1,  //
    V6 = 2,
}
```

연관 값이 없는 enum은 `as` 연산자로 정수와 직접 타입 변환할 수 있습니다.

열거 타입 정의는 제네릭을 지원합니다. 열거의 멤버는 새로운 제네릭을 도입할 수 없습니다.

> **계획 중인 기능**: 비망라적 열거(non-exhaustive enum) 정의를 지원합니다. 문법은 마지막 멤버 뒤에 생략 부호를 사용하는 것입니다:
```rust
enum Puctuation {
    Comma,
    Dot,
    Semi,
    ...  // 생략 부호, Rust에서 #[non_exhaustive]로 enum을 수식하는 것과 같음
}
```

## 공용체 union

공용체는 키워드 `union`으로 정의합니다. 공용체의 전체 크기는 가장 큰 멤버의 크기에 따라 결정됩니다.

```
union U {
    data1: Byte,
    data2: UInt,
}
```

union 타입은 안전하지 않으며, union 타입 멤버의 읽기·쓰기는 모두 unsafe 컨텍스트에서 해야 합니다.

union의 초기화 문법은 struct 초기화 문법과 비슷합니다. 하지만 멤버 중 하나만 선택해 초기화해야 합니다.

non-trivial 타입은 union 타입의 멤버 변수로 쓸 수 없습니다.
non-trivial 타입은 다음을 포함합니다:
1. 소멸자가 있는 타입, 예: Arc/Weak 등
2. 수명 매개변수가 있는 타입, 예: &/&mut 등
3. struct의 멤버 변수에 non-trivial 타입이 있으면, 그 struct는 non-trivial입니다
4. enum의 연관 값에 non-trivial 타입이 있으면, 그 enum은 non-trivial입니다
5. 배열 타입의 원소가 non-trivial 타입이면, 그 배열은 non-trivial입니다
6. tuple 타입의 원소에 non-trivial 타입이 포함되면, 그 tuple은 non-trivial입니다

union 타입 정의는 제네릭 매개변수를 붙일 수 없습니다.

union의 주요 사용 장면은 두 가지입니다:
1. C와 상호 작용하는 장면
2. 비트 단위 타입 변환 장면 (rust의 `std::mem::transmute`와 유사)

예를 들어 `F32` 타입을 비트 단위로 `UInt32` 타입으로 바꾸고 싶다면, union의 도움을 받아 완료할 수 있습니다:
```rust
union FloatOrInt {
    f: F32,
    i: UInt32,
}

fn bit_cast_f32_to_uint32(f: F32) -> UInt32 {
    let u: FloatOrInt = { .f = f };
    return unsafe(u.i);
}
```

## 타입의 크기

타입은 Sized와 UnSized로 나뉩니다. Sized 타입은 지역 변수, 전역 변수, 멤버 변수로 쓸 수 있지만, UnSized 타입은 그렇지 않으며 포인터를 통해 간접 접근만 할 수 있습니다.

UnSized 타입은 다음을 포함합니다:
1. `extern type`으로 선언된 타입
    * `extern type`은 주로 상호 운용 장면에 쓰입니다. 의미는 어떤 타입의 정의가 다른 언어에 있고, zinc에서는 그 타입의 정의를 가져올 수 없다는 것입니다. 따라서 크기를 알 수 없고, 멤버 변수에 직접 접근할 수 없습니다.

2. 모든 trait
    * `trait R`을 정의했다고 가정하면, 변수의 타입이 `R`이라고 선언할 수는 없지만 `&R / &mut R / *R` 등은 가능합니다

3. 명시적으로 `impl UnSized for S {}`한 사용자 정의 타입 `S`
    * `UnSized`는 내장 trait이며, 사용자가 사용자 정의 타입도 Unsized임을 지정할 수 있습니다. 방식은 `impl UnSized for MyType {}`입니다.
        이렇게 하는 목적은 이 타입을 “값 의미론 타입”으로 쓰는 것을 금지하고, 포인터로만 가리켜 쓰게 하려는 것입니다. 이 타입은 “참조 의미론 타입”만 있으면 됩니다.
        전형적인 장면이 표준 라이브러리의 `File` 타입입니다. 이 타입은 사용자가 “값 의미론 타입” 방식으로 쓰는 것을 허용하지 않으며, 사용자는 `File`을 가리키는 포인터 타입만 얻을 수 있습니다.

제네릭 장면에서는 현재 UnSized 타입을 제네릭 실인자로 쓸 수 없습니다.
