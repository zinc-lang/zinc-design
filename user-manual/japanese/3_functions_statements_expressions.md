## 式、文、関数

## 式

zinc 言語は式言語ではない。
1. `break` `continue` `return` `goto` `panic` などのキーワードは、文の中でだけ使え、式の中で直接は使えない。
2. 値を生み出せるのは式だけである。文はできない。
3. 文は式を含められるが、式は文を直接含められない。lambda 式は例外であり、文を含められるが、それが含む文中の return/break/continue は lambda 内部にだけ影響し、lambda は対外的には依然として式の特徴を示し、制御フロー転移はできない。

ユーザが一つの式の中で、比較的複雑な文を順に実行し、最終的に一つの値を生み出したいなら、lambda を使って直ちに呼び出してほしい。
lambda 内部の制御フロー文は、lambda の関数本体内でのみ作用し、外部の式には影響しない。

### 演算子式

#### `Result` 型

Zinc は `Result<R, E>` をエラー処理の主な機構として使う。これは標準ライブラリで定義された一つの enum である：
```
enum Result<R, E> {
    Ok(R), Err(E)
}
```

`Result<R, E>` 中の `E` はエラー情報を表す。ユーザは任意の型でエラー情報を記述できる。

* エラーの可能性が非常に限られた数種類だけなら、enum をエラー情報として設計するのはとても合理的である。

* エラー情報を log 印字にだけ使うなら、単純に文字列をエラー型として使っても問題ない。

* エラー型を多階層に分類する必要があるなら、一組の `trait MyBussinessError` とその継承体系を設計し、`*MyBussinessError` を返すエラー型とするのも良い設計である。

* 関数定義側が、呼び出し側に具体的なエラー型を気にさせたくないなら、一律 `Result<R, *Any>` を返せばよい。任意のエラー型は box したあと、`*Any` に変換できる。
呼び出し側は必要に応じてダウンキャストし、自分が処理する必要のある部分のエラー型だけを処理できる。

* 呼び出し側にエラー発生時の関数呼び出しスタックを渡したいなら、カスタム型で標準ライブラリ中の `BackTrace` 型を包み、エラー型として使える。
`BackTrace` 型は現在の呼び出しスタックを記述でき、それをエラー情報の一部として外へ渡せばよい。

#### `?` 演算子

`?` 演算子は接尾辞演算子であり、使い方は `expr?` である。

`?` 演算子は主に `Result` 型と組み合わせて使うためのものである。`?` 演算子は、その前のこの式の型が `Result` であることを要求する。

> **計画中の機能**：今後 `?` 演算子のオーバーロードをサポートし、カスタム型をサポートできるようにする。

`let x = expr?;` 文の実行意味論は：

```
match(expr) {
    Ok(r) => {
        let x = r;
    }
    Err(e) => {
        return Err(e);
    }
}
```

これは関数全体の早期 return を引き起こすため、この関数の戻り型に対する要求がある。
`expr` の型が `Result<R1, E1>` で、関数の戻り型が `Result<R2, E2>` なら、`E2` が `E1` へ自然に暗黙変換できるか、あるいは `E2` が `From<E1>` という trait を実装していることが要求される。
こうして初めてコンパイラは `E1` を `E2` に変換して返す能力を持つ。

### 丸括弧式

`unsafe(<expr>)` を許す。このとき `<expr>` 式は unsafe コンテキスト中にある。かつその式の値は、`<expr>` 式の値に等しい。

`const(<expr>)` を許す。このとき `<expr>` 式は const コンテキスト中にある。かつその式は、コンパイル時に評価されなければならない。

### クロージャ式

zinc のクロージャ構文は rust と異なる。zinc がクロージャ構文を設計するときの主な考慮点は次のとおりである：
1. クロージャ構文は「後置呼び出し」糖衣構文に適している必要がある。後置呼び出し構文は多くの場面で、美しく見栄えの良い DSL を設計できる。たとえば lock / spawn / lazy などの関数は、いずれも後置クロージャ構文に非常に適している。
2. クロージャには完全な書き方も、簡略な書き方も必要である
3. 完全な書き方のクロージャ構文は、機能が充実していなければならず、明示的キャプチャリスト、ジェネリック宣言、完全な引数リスト、明示的戻り型をサポートする必要がある
4. 簡略な書き方は十分に簡略で、不要な構文要素をすべて省略できるが、完全な書き方との類似性も必要である

完全な書き方のクロージャ構文の例は次のとおり：
```
.{
    async [move x, weak y, ref z]<T>(arg: T) -> ReturnTy where T: Constrait
    =>
    statements(x, arg);
    return y;
}
```

完全なクロージャ構文は `.{` で始まり、`}` で終わり、「後置呼び出し」構文との組み合わせが容易である。内部に含む内容は：
1. qualifier 修飾子リスト。`async` `const` などを含む
2. 角括弧に含まれる明示的キャプチャリスト。キャプチャモードは `move` `ref` `ref mut` `weak` をサポートする
3. 山括弧に含まれるジェネリック引数リスト
4. 丸括弧に含まれる関数引数リスト
5. `->` の後ろに続く明示的戻り型
6. 任意の where 条件
7. `=>` の後ろに続くクロージャ関数本体

最も簡略な書き方の例は次のとおり：
```
(x) => x + x
```
丸括弧の中は引数リストであり、引数は型宣言を省略できる。`=>` の後ろはクロージャ関数本体であり、波括弧がない場合、この関数本体は一つの式だけであり、文を含められない。

### ループ文

#### `while`

1. while の後ろの条件は Bool 型の式でなければならない
2. while の波括弧の後ろにセミコロンを書く必要はない

#### `do-while`

1. while の後ろの条件は Bool 型の式でなければならない
2. do-while は文の終わりに必ずセミコロンを書かなければならない

#### `for`

`for  <pattern> in <expr>  { <statements> }`

1. for はパターンマッチをサポートする
2. expr は `Iterable` または `IterableMut` trait を満たす型、あるいはそのような型を指すポインタでなければならない。

`for-in` 文の脱糖方式は三通りあり、`<pattern>` の書き方に依存する：

1. pattern が identifier のとき：`for i in v { <body> }`。このとき `i` の型は `v` の `Iterable::Item` 型である。脱糖すると：

    ```
    {
        let mut iter = v.iter();
        while (iter.next() is Some(p)) { // p は Item を指す読み取り専用借用
            let i = *p;                // i は読み取り専用借用からコピーした新しい Item
            <body>
        }
    }
    ```

2. pattern が ref identifier のとき：`for ref i in v { <body> }`。このとき `i` の型は `v` の `&Iterable::Item` 型である。脱糖すると：

    ```
    {
        let mut iter = v.iter();
        while (iter.next() is Some(i)) { // i は Item を指す読み取り専用借用
            <body>
        }
    }
    ```

3. pattern が ref mut identifier のとき：`for ref mut i in v { <body> }`。このとき `i` の型は `v` の `&mut Iterable::Item` 型である。脱糖すると：

    ```
    {
        let mut iter = v.iter_mut();
        while (iter.next() is Some(i)) { // i は Item を指す読み書き可能借用
            <body>
        }
    }
    ```

### ジャンプ文

#### `return`

1. return の後ろには式を付けても付けなくてもよい。
2. return の後ろの式の型は、関数の戻り型と互換でなければならない。

#### `break`

1. break はループブロック中でのみ使える。`while` `do-while` `for` を含む。

#### `continue`

1. continue はループブロック中でのみ使える。`while` `do-while` `for` を含む。

#### `panic`

panic キーワードは、C++/Java などの言語の throw キーワードに類比できる。しかし Zinc には try-catch 構文がなく、`catch_unwind` 関数も提供しない。

回復不能なエラーが起きたときにだけ、panic を使うべきである。panic キーワードの後ろには文字列型の式を続けられる。例は次のとおり：

```rust
fn unwrap<T>(o: Option<T>) -> T {
    if o is Some(v) {
        return v;
    } else {
        panic "unwrap Option failed";
    }
}
```

#### `goto`

`goto` は予約キーワードであり、当面未実装である。いくつかの目的のために用意している。

1. label ラベル文と組み合わせて、ジャンプ機能を実現する。rust の break label 文の代わりである。主に break label の使用場面が限られ、ループブロック中でしか使えないからである。しかし goto label には C 言語でもっとよく使われる場面がある：エラー処理を関数末尾にまとめて書き、関数の他の場所でエラーに遭遇したらすべてここに goto して統一処理する、というものである。こう書くのは極めて便利で読みやすい。この場面で goto を使うのは非常に合理的である。もちろん、プログラマの濫用を避けるため、goto 文にはいくつかの制限を設けるべきである：
    1. goto は文であり、式の中では使えない。
    2. 関数や lambda をまたいでジャンプできない。
    3. block から飛び出すことだけができ、block に飛び込むことはできない。ループ本体、match の異なる分岐も異なる block である。
    4. 後ろへジャンプすることだけができ、前へジャンプすることは許さない。
    5. goto 経路上で、すべての変数が先に初期化されてから使われることを保証しなければならない。

    要するに、安全で信頼性のある goto 文を提供したい。C 言語でよく使われる、関数末尾での統一エラー処理というプログラミング様式を実現でき、しかも他のリスクをもたらさないようにする。

2. 「決定的末尾再帰」特性のために用意する。rust の `become` キーワードの代わりである。
    1. `goto call_fn();` によって決定的末尾再帰を実現することを許す。


## 関数

関数定義は `fn` キーワードで始まり、その後に関数名と引数リストが続き、引数リストは丸括弧で囲み、続いて任意の戻り型があり、最後が波括弧で囲まれた関数本体である。

```rust
// 関数定義
fn function_name(arg1: Int, arg2: Char) -> Bool {
    println("function body");
    return true;
}

fn main() {
    function_name(0, 'X'); // 関数呼び出し
}
```

戻り型を省略すると、`()` 型を返すことを表す。

引数は名前付き引数をサポートし、名前付き引数は小数点で始まる。呼び出すときに名前付き引数を使う場合も、小数点で始める。小数点構文を使うのは、構造体初期化式の構文と一致させるためである。
名前付き引数は、名前なし引数の後ろになければならない。

```
fn run(.from: &Str, .to: &Str) {
    println("run from {} to {}", from, to);
}

fn main() {
    run("home", "bar");  // 引数の順序どおりに呼べる
    run(.to = "bar", .from = "home"); // 名前で呼ぶこともでき、このとき順序は重要でない。
}
```

関数が名前付き引数をサポートしたため、さらに引数のパターンマッチをサポートするとやや複雑になる。まして関数引数の位置では、ほとんどのパターンはあまり役に立たないため、関数の引数はパターンマッチをサポートしない。
Rust では、引数リストがサポートする最も有用なパターンの一つが `mut` パターンであり、引数自体の変更を許す。zinc では、次の仕方で回避することを勧める：
```
fn f(v: Vec<Int>) {
    let mut v = move v; // 引数中の v は mut 修飾がなく、関数内部で同名の mut 変数をさらに定義し、引数を move してくればよい。
    // ...
    v.push(2); // v の &mut 型借用を得る必要があり、ここでは変数 v が mut 修飾されていることが要求される
    // ...
}
```

引数はデフォルト値をサポートし、デフォルト値は定数式でなければならない。デフォルト値付きの引数は、デフォルト値のない引数の後ろになければならない。

```
fn increase(value: Int = 1) {}

fn main() {
    increase();  // 実引数の値は 1
    increase(2); // 実引数の値は 2
}
```

後置クロージャをサポートする。後置クロージャ呼び出し構文の意味は：関数定義時に、最後の引数の型が fn/Fn/FnMut 型、あるいはそれらを指すポインタ型であるなら、呼び出すときに lambda を引数リストの外に書いてよい、ということである。
この関数型引数以外に他の引数がなければ、呼び出し側は引数リストに必要な丸括弧を省略できる。
例は次のとおり：

```
// 関数 lock の最後の引数は関数型である
fn lock(f: &Fn()) {
    println("lock");
    f();
    println("unlock");
}

fn main() {
    lock( ()=>println("smth") ); // OK, 単純構文の lambda を引数とする
    lock( .{ () => println("smth"); } ); // OK, 完全構文の lambda を引数とする

    // 後置クロージャ呼び出し構文。クロージャを引数リストの外に書く
    lock().{
        () => println("smth");
    };
    // 後置クロージャ呼び出し構文。他の引数がないとき、引数リストの丸括弧を省略する
    lock.{
        () => println("smth");
    };
    // 今後さらに lambda の構文を簡略化し、=> 記号の省略を許せる
    lock.{
        println("smth");
    };
}
```

関数オーバーロードをサポートする。ただし引数個数が異なることが要求される。

```
fn f1(arg1: Int, arg2: Int = 1) {} // 1 個の引数または 2 個の引数を受け付けることを許す。
fn f1(arg: String) {} // 誤り。上の f1 とオーバーロードを形成できない。この版は 1 個の引数を受け付けることを許し、上の版も許す。衝突が起きる。
```

`impl` ブロックによって型にメンバ関数を追加することをサポートする。
最初の引数名が `self` キーワードのとき、小数点形式で関数を呼べる。

```rust
impl User {
    fn send_email(&self) {}
}
fn main() {
    let u: User = { ... };
    u.send_email();
}
```

`self` 引数は特殊であり、いくつかの簡略書き方がある：
* `self` は `self: Self` を表す
* `&self` は `self: &Self` を表す
* `&mut self` は `self: &mut Self` を表す
* `*self` は `self: *Self` を表す
* `*weak self` は `self: *weak Self` を表す

関数は第一級市民として使える。関数ポインタ型をサポートする。
