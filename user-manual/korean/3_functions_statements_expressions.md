## 표현식, 문장, 함수

## 표현식

zinc 언어는 표현식 언어가 아닙니다.
1. `break` `continue` `return` `goto` `panic` 등 키워드는 문장에서만 쓸 수 있고, 표현식에 직접 쓸 수 없습니다.
2. 표현식만이 값을 생성할 수 있습니다. 문장은 할 수 없습니다.
3. 문장은 표현식을 포함할 수 있지만, 표현식은 문장을 직접 포함할 수 없습니다. lambda 표현식은 예외로, 문장을 포함할 수 있지만 그 안의 return/break/continue는 lambda 내부에만 영향을 주고, lambda는 바깥으로는 여전히 표현식의 특징을 보이며 제어 흐름 전이를 할 수 없습니다.

사용자가 하나의 표현식 안에서 비교적 복잡한 문장을 순서대로 실행하고 최종적으로 값을 만들어야 한다면, lambda를 쓰고 즉시 호출하십시오.
lambda 내부의 제어 흐름 문장은 lambda의 함수 본체 안에서만 작용하며, 바깥 표현식에는 영향이 없습니다.

### 연산자 표현식

#### `Result` 타입

Zinc는 `Result<R, E>`를 오류 처리의 주요 메커니즘으로 사용합니다. 표준 라이브러리에 정의된 enum입니다:
```
enum Result<R, E> {
    Ok(R), Err(E)
}
```

`Result<R, E>`의 `E`는 오류 정보를 나타냅니다. 사용자는 어떤 타입이든 오류 정보를 기술하는 데 쓸 수 있습니다.

* 오류 가능성이 매우 제한된 몇 가지뿐이라면, enum을 오류 정보로 설계하는 것이 합리적입니다.

* 오류 정보를 log 출력에만 쓴다면, 단순히 문자열을 오류 타입으로 써도 문제없습니다.

* 오류 타입을 여러 계층으로 분류해야 한다면, `trait MyBussinessError`와 그 상속 체계를 설계하고 `*MyBussinessError`를 반환 오류 타입으로 쓰는 것도 좋은 설계입니다.

* 함수 정의 측이 호출 측이 구체적인 오류 타입을 신경 쓰지 않아도 된다면, 통일해서 `Result<R, *Any>`를 반환하면 됩니다. 어떤 오류 타입이든 box한 뒤에는 `*Any`로 변환할 수 있습니다.
호출 측은 필요에 따라 다운캐스트하여, 자신이 처리해야 하는 그 부분의 오류 타입만 처리할 수 있습니다.

* 호출 측이 오류 발생 시의 함수 호출 스택을 얻기를 원한다면, 사용자 정의 타입으로 표준 라이브러리의 `BackTrace` 타입을 감싸 오류 타입으로 쓸 수 있습니다.
`BackTrace` 타입은 현재 호출 스택을 기술할 수 있으므로, 이를 오류 정보의 일부로 바깥에 전달하면 됩니다.

#### `?` 연산자

`?` 연산자는 접미사 연산자이며, 사용 방식은 `expr?`입니다.

`?` 연산자는 주로 `Result` 타입과 함께 쓰입니다. `?` 연산자는 앞의 표현식 타입이 `Result`일 것을 요구합니다.

> **계획 중인 기능**: 이후 `?` 연산자의 오버로드를 지원해 사용자 정의 타입을 지원하게 합니다.

`let x = expr?;` 문장의 실행 의미론은 다음과 같습니다:

```
match(expr) {
    Ok(r) => {
        let x = r;
    }
    Err(e) => {
        return Err(e);
    }
}
```

함수 전체를 조기 반환하게 하므로, 이 함수의 반환 타입에 요구가 있습니다.
`expr`의 타입이 `Result<R1, E1>`이고 함수의 반환 타입이 `Result<R2, E2>`이면, `E2`가 `E1`으로 자연스럽게 암시 변환되거나, `E2`가 `From<E1>` trait을 구현해야 합니다.
그래야 컴파일러가 `E1`을 `E2`로 변환해 반환할 수 있습니다.

### 클로저 표현식

zinc의 클로저 문법은 rust와 다릅니다. zinc가 클로저 문법을 설계할 때 주로 고려한 점은 다음과 같습니다:
1. 클로저 문법은 “후행 호출” 문법 설탕에 적합해야 합니다. 후행 호출 문법은 많은 장면에서 아름답고 예쁜 DSL을 설계할 수 있습니다. 예를 들어 lock / spawn / lazy 등 함수는 후행 클로저 문법에 매우 적합합니다.
2. 클로저는 완전한 표기와 간략 표기가 모두 있어야 합니다
3. 완전한 표기의 클로저 문법은 기능이 완비되어야 하며, 명시적 캡처 목록, 제네릭 선언, 완전한 매개변수 목록, 명시적 반환 타입을 지원해야 합니다
4. 간략 표기는 충분히 간략해 불필요한 문법 요소를 모두 생략할 수 있어야 하지만, 완전한 표기와 유사도도 있어야 합니다

완전한 표기의 클로저 문법 예시는 다음과 같습니다:
```
.{
    async [move x, weak y, ref z]<T>(arg: T) -> ReturnTy where T: Constrait
    =>
    statements(x, arg);
    return y;
}
```

완전한 클로저 문법은 `.{`로 시작하고 `}`로 끝나, “후행 호출” 문법과 맞추기 쉽습니다. 내부에 포함되는 내용은 다음과 같습니다:
1. qualifier 수식어 목록, `async` `const` 등 포함
2. 대괄호에 담긴 명시적 캡처 목록, 캡처 모드는 `move` `ref` `ref mut` `weak`를 지원
3. 꺾쇠괄호에 담긴 제네릭 매개변수 목록
4. 소괄호에 담긴 함수 매개변수 목록
5. `->` 뒤에 따르는 명시적 반환 타입
6. 선택적인 where 조건
7. `=>` 뒤에 따르는 클로저 함수 본체

가장 간략한 표기 예시는 다음과 같습니다:
```
(x) => x + x
```
소괄호 안은 매개변수 목록이며, 매개변수는 타입 선언을 생략할 수 있습니다. `=>` 뒤는 클로저 함수 본체이며, 중괄호가 없으면 이 함수 본체는 하나의 표현식만 가능하고 문장을 포함할 수 없습니다.

### 반복 문장

#### `while`

1. while 뒤의 조건은 반드시 Bool 타입 표현식이어야 합니다
2. while의 중괄호 뒤에는 세미콜론을 쓸 필요가 없습니다

#### `do-while`

1. while 뒤의 조건은 반드시 Bool 타입 표현식이어야 합니다
2. do-while은 문장 끝 마지막에 반드시 세미콜론을 써야 합니다

#### `for`

`for  <pattern> in <expr>  { <statements> }`

1. for는 패턴 매칭을 지원합니다
2. expr은 반드시 `Iterable` 또는 `IterableMut` trait을 만족하는 타입이거나, 그런 타입을 가리키는 포인터여야 합니다.

`for-in` 문장의 설탕 제거 방식은 세 가지이며, `<pattern>`의 표기에 따라 달라집니다:

1. pattern이 identifier인 경우: `for i in v { <body> }`, 이때 `i`의 타입은 `v`의 `Iterable::Item` 타입입니다. 설탕 제거 결과는 다음과 같습니다:

    ```
    {
        let mut iter = v.iter();
        while (iter.next() is Some(p)) { // p는 Item을 가리키는 읽기 전용 빌림
            let i = *p;                // i는 읽기 전용 빌림에서 복사한 새로운 Item
            <body>
        }
    }
    ```

2. pattern이 ref identifier인 경우: `for ref i in v { <body> }`, 이때 `i`의 타입은 `v`의 `&Iterable::Item` 타입입니다. 설탕 제거 결과는 다음과 같습니다:

    ```
    {
        let mut iter = v.iter();
        while (iter.next() is Some(i)) { // i는 Item을 가리키는 읽기 전용 빌림
            <body>
        }
    }
    ```

3. pattern이 ref mut identifier인 경우: `for ref mut i in v { <body> }`, 이때 `i`의 타입은 `v`의 `&mut Iterable::Item` 타입입니다. 설탕 제거 결과는 다음과 같습니다:

    ```
    {
        let mut iter = v.iter_mut();
        while (iter.next() is Some(i)) { // i는 Item을 가리키는 읽기·쓰기 빌림
            <body>
        }
    }
    ```

### 점프 문장

#### `return`

1. return 뒤에는 표현식을 붙일 수도 있고 없을 수도 있습니다.
2. return 뒤 표현식의 타입은 반드시 함수 반환 타입과 호환되어야 합니다.

#### `break`

1. break는 반복 블록에서만 쓸 수 있습니다. `while` `do-while` `for`를 포함합니다.

#### `continue`

1. continue는 반복 블록에서만 쓸 수 있습니다. `while` `do-while` `for`를 포함합니다.

#### `panic`

panic 키워드는 C++/Java 등 언어의 throw 키워드에 비유할 수 있습니다. 하지만 Zinc에는 try-catch 문법이 없고, `catch_unwind` 함수도 제공하지 않습니다.

복구할 수 없는 오류가 발생했을 때만 panic을 써야 합니다. panic 키워드 뒤에는 문자열 타입 표현식을 붙일 수 있습니다. 예시는 다음과 같습니다:

```rust
fn unwrap<T>(o: Option<T>) -> T {
    if o is Some(v) {
        return v;
    } else {
        panic "unwrap Option failed";
    }
}
```

#### `goto`

`goto`는 예약된 키워드이며 잠시 구현되지 않았습니다. 여러 목적을 위해 준비되어 있습니다.

1. label 레이블 문장과 함께 점프 기능을 구현합니다. rust의 break label 문장을 대체합니다. 주로 break label의 사용 장면이 제한되어 반복 블록에서만 쓸 수 있기 때문입니다. 하지만 goto label은 C 언어에서 더 자주 쓰이는 장면이 있습니다. 바로 오류 처리를 함수 끝에 통일해 쓰고, 함수의 다른 곳에서 오류를 만나면 모두 여기로 goto해 통일 처리하는 것입니다. 이렇게 쓰면 극히 편리하고 읽기 쉽습니다. 이 장면에서 goto를 쓰는 것은 매우 합리적입니다. 물론 프로그래머의 남용을 피하려면 goto 문장에 몇 가지 제한을 두어야 합니다:
    1. goto는 문장이며, 표현식 안에서 쓸 수 없습니다.
    2. 함수, lambda를 넘어 점프할 수 없습니다.
    3. block 밖으로만 점프할 수 있고, block 안으로 점프할 수 없습니다. 반복 본체, match의 서로 다른 분기도 서로 다른 block입니다.
    4. 뒤로만 점프할 수 있고, 앞으로 점프하는 것은 허용되지 않습니다.
    5. goto 경로 상의 모든 변수가 먼저 초기화된 뒤 사용된다는 것을 반드시 보장해야 합니다.

    요약하면, 저는 안전하고 신뢰할 수 있는 goto 문장을 제공하고 싶습니다. C 언어에서 흔히 쓰는, 함수 끝에서 오류를 통일 처리하는 프로그래밍 모델을 구현할 수 있으면서, 다른 위험을 가져오지 않아야 합니다.

2. “결정적 꼬리 재귀” 특성을 위해 준비합니다. rust의 `become` 키워드를 대체합니다.
    1. `goto call_fn();`으로 결정적 꼬리 재귀를 구현하는 것을 허용합니다.


## 함수

함수 정의는 `fn` 키워드로 시작하고, 그다음에 함수 이름과 매개변수 목록이 오며, 매개변수 목록은 원괄호로 둘러싸고, 이어서 선택적 반환 타입이 오고, 마지막은 중괄호로 둘러싼 함수 본체입니다.

```rust
// 함수 정의
fn function_name(arg1: Int, arg2: Char) -> Bool {
    println("function body");
    return true;
}

fn main() {
    function_name(0, 'X'); // 함수 호출
}
```

반환 타입을 생략하면 `()` 타입을 반환함을 나타냅니다.

매개변수는 이름 있는 매개변수를 지원하며, 이름 있는 매개변수는 소수점으로 시작합니다. 호출할 때 이름 있는 매개변수를 쓰면, 역시 소수점으로 시작합니다. 소수점 문법을 쓰는 이유는 구조체 초기화 표현식 문법과 일치시키기 위함입니다.
이름 있는 매개변수는 반드시 이름 없는 매개변수 뒤에 와야 합니다.

```
fn run(.from: &Str, .to: &Str) {
    println("run from {} to {}", from, to);
}

fn main() {
    run("home", "bar");  // 매개변수 순서로 호출할 수 있음
    run(.to = "bar", .from = "home"); // 이름으로 호출할 수도 있으며, 이때 순서는 중요하지 않음.
}
```

함수가 이름 있는 매개변수를 지원하므로, 매개변수의 패턴 매칭을 다시 지원하면 다소 복잡해집니다. 게다가 함수 매개변수 위치에서는 대부분의 패턴이 별로 쓸모가 없으므로, 함수의 매개변수는 패턴 매칭을 지원하지 않습니다.
Rust에서 매개변수 목록이 지원하는 가장 유용한 패턴 하나가 `mut` 패턴으로, 매개변수 자체를 수정할 수 있게 합니다. zinc에서는 다음 방식으로 우회하기를 권합니다:
```
fn f(v: Vec<Int>) {
    let mut v = move v; // 매개변수의 v에는 mut 수식이 없으므로, 함수 내부에 같은 이름의 mut 변수를 다시 정의하고 매개변수를 move해 오면 됨.
    // ...
    v.push(2); // v의 &mut형 빌림을 얻어야 하며, 여기서는 변수 v에 mut 수식이 있어야 함
    // ...
}
```

매개변수는 기본값을 지원하며, 기본값은 반드시 상수 표현식이어야 합니다. 기본값이 있는 매개변수는 반드시 기본값이 없는 매개변수 뒤에 와야 합니다.

```
fn increase(value: Int = 1) {}

fn main() {
    increase();  // 실인자의 값은 1
    increase(2); // 실인자의 값은 2
}
```

후행 클로저를 지원합니다. 후행 클로저 호출 문법의 의미는 다음과 같습니다. 함수 정의 시 마지막 매개변수의 타입이 fn/Fn/FnMut 타입이거나 그들을 가리키는 포인터 타입이면, 호출할 때 lambda를 매개변수 목록 바깥에 쓸 수 있습니다.
이 함수 타입 매개변수 외에 다른 매개변수가 없으면, 호출 측은 매개변수 목록에 필요한 소괄호를 생략할 수 있습니다.
예시는 다음과 같습니다:

```
// 함수 lock의 마지막 매개변수는 함수 타입
fn lock(f: &Fn()) {
    println("lock");
    f();
    println("unlock");
}

fn main() {
    lock( ()=>println("smth") ); // OK, 단순 문법의 lambda를 매개변수로
    lock( .{ () => println("smth"); } ); // OK, 완전한 문법의 lambda를 매개변수로

    // 후행 클로저 호출 문법, 클로저를 매개변수 목록 바깥에 씀
    lock().{
        () => println("smth");
    };
    // 후행 클로저 호출 문법, 다른 매개변수가 없을 때 매개변수 목록의 소괄호를 생략
    lock.{
        () => println("smth");
    };
    // 이후 lambda 문법을 더 단순화해 => 기호를 생략하는 것도 허용할 수 있음
    lock.{
        println("smth");
    };
}
```

함수 오버로드를 지원합니다. 하지만 매개변수 개수가 달라야 합니다.

```
fn f1(arg1: Int, arg2: Int = 1) {} // 1개 또는 2개 매개변수를 받을 수 있음.
fn f1(arg: String) {} // 오류, 위의 f1과 오버로드를 이룰 수 없음. 이 버전은 1개 매개변수를 받을 수 있고, 위 버전도 받을 수 있음. 충돌 발생.
```

`impl` 블록으로 타입에 멤버 함수를 추가하는 것을 지원합니다.
첫 번째 매개변수 이름이 `self` 키워드일 때, 소수점 형식으로 함수를 호출할 수 있습니다.

```rust
impl User {
    fn send_email(&self) {}
}
fn main() {
    let u: User = { ... };
    u.send_email();
}
```

`self` 매개변수는 특수하며, 몇 가지 간소화 표기가 있습니다:
* `self`는 `self: Self`를 나타냅니다
* `&self`는 `self: &Self`를 나타냅니다
* `&mut self`는 `self: &mut Self`를 나타냅니다
* `*self`는 `self: *Self`를 나타냅니다
* `*weak self`는 `self: *weak Self`를 나타냅니다

함수는 일급 시민으로 쓸 수 있습니다. 함수 포인터 타입을 지원합니다.
