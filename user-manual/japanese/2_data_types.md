
# 基本データ型

命名規則：すべての具名型について、型名はアッパーキャメルケース UpperCamelCase である。（`fn` キーワードは除く。このキーワードは主に関数定義の場面で使うからである。）

## Bool 型

`Bool` 型には可能な値が二つあり、`true` と `false` である。

`Bool` 型の否定には `!` 演算子を使う。

## 整数

|  長さ |  符号付き  |  符号なし  |
|-------|---------|----------|
| 8 bit | Int8      |  UInt8      |
| 16 bit | Int16      |  UInt16      |
| 32 bit | Int32      |  UInt32      |
| 64 bit | Int64      |  UInt64      |
| arch-dependent | Int      |  UInt  |
| arch-dependent | Short    | UShort  |

Int/UInt 型の大きさは、対象プラットフォームに依存する。64 ビットプラットフォームでは 64 bit の大きさであり、32 ビットプラットフォームでは 32 bit の大きさである。C 言語の `intptr_t` / `uintptr_t` に相当する。
Short/UShort 型の大きさは対象プラットフォームに依存し、常に Int/UInt 型の半分である。64 ビットプラットフォームでは 32 bit の大きさであり、32 ビットプラットフォームでは 16 bit の大きさである。


整数リテラルは、`_` を区切りとして許す。

接頭辞で進数を区別できる。`0o` は八進、`0x` は十六進、`0b` は二進を表す。

整数リテラルは型接尾辞を許す。接尾辞の型は小文字であり、たとえば `123_i8`  `100_i`  `0x64_u` である。
他の文脈情報がない場合、整数リテラルから型を推論できない。ユーザは整数リテラルに型接尾辞を付け、型を明示することを勧める。

整数の算術演算は、オーバーフロー時は一律 wrapping モードである。他の振る舞いが必要なら、標準ライブラリを呼び出してほしい。標準ライブラリは整数に `checked_add` などのメンバ関数を提供する（未実装）。

zinc は「ビット演算」演算子を提供しない。左シフト、右シフト、ビット積、ビット和、ビット否定、ビット排他的論理和を含む。
代わりに標準ライブラリで整数型にメンバ関数を提供してビット演算を行い、たとえば `bit_and` であり、機能要件を十分満たせる。

理由：ビット演算操作の使用頻度は低く、しかも整数型にしか適用できず、専用の演算子を設計するのはやや無駄である。
ましてビット演算は上記の機能だけにとどまらず、rotate、reverse、count_ones などあまり使われない十種前後のビット演算機能もある。これらはもともとメンバ関数でしか提供できない。個人的には、すべてのビット演算機能をメンバ関数で提供する方が一貫していると感じる。
ASCII コード中の記号はもともとあまり足りておらず、これらの記号は他のより重要な機能のために残す方が合理的である。


## 浮動小数点数

浮動小数点数は `F32` と `F64` 型に分かれる。

浮動小数点リテラルは、`_` を区切りとして許す。
浮動小数点リテラルは型接尾辞を許し、それぞれ `f32` と `f64` である。

浮動小数点リテラルは、小数点の前の 0 を省略できない。`.123` や `-.1` はいずれもエラーになる。

## 文字型 Char

`Char` 型は 32 bit であり、一つの unicode code point を表す。

`Char` リテラルは単引用符で囲む。たとえば `'好'`。

`Char` リテラルはエスケープを許す。`'\u{3456}'`。

Byte リテラルをサポートする。`b'a'`。Byte リテラルの値は ascii 文字だけであり、その型は `UInt8` である。

標準ライブラリには型別名定義 `type Byte = UInt8;` がある。

## 配列

配列内の要素はすべて同じ型である。配列の長さはコンパイル時定数でなければならない。

要素が `T` 型、長さが `N` の配列型は、`[T; N]` と表す。配列は値型であり、配列型は代入、引数渡し、返却のときにすべての要素をコピーする。

例は次のとおり：

```rust
fn main() {
    let x: [Int; 3] = [1, 2, 3];
}
```

配列リテラルには二通りの表現形式がある：

1. 角括弧の中にすべての要素を直接列挙し、カンマで区切る。

    `[1, 2, 3]`

2. 角括弧の中で要素と個数をセミコロンで区切り、複数の繰り返し要素を表す。

    `[1; 3]`

配列要素へのアクセスにはインデックス式を使い、範囲外のときは panic になる。例は次のとおり：

```rust
fn main() {
    let mut x: [Int; 3] = [1, 2, 3];
    x[1] = 10;
    println(x[5]); // コンパイルは通るが、実行段階で panic になる
}
```

## スライス

配列スライスは、配列の一部を指す借用ポインタである。配列スライスは二種類あり、`Slice<'a, T>` と `SliceMut<'a, T>` で、それぞれ読み取り専用権限と読み書き可能権限を表す。

```rust
fn main() {
    let x: [Int; 3] = [1, 2, 3];
    let s: Slice<Int> = &x;
    println(s.len());
    println(s[1]);
}
```

配列スライスはライフタイム付きの構造体であり、追加のメタデータを持つ借用ポインタと見なせる。上例の `s` 変数は二つのポインタサイズであり、それぞれ先頭アドレスと長さを保存する。

注：rust の `&[T]` 構文を使わないのは、型システムと実装難度を簡略化したいからである。
rust では `[T]` は合法な型であり、独立して使え、かつ dyn sized である。これは型システムに一種の特例をもたらし、ジェネリクスを実装するときに非常に面倒である。zinc はユーザが `&[T]/&mut [T]` 型だけを使えるようにし、単独の dyn sized な `[T]` 型もなく、`Box<[T]>` `Rc<[T]>` などの型もないようにしたい。
したがって `&[T]/&mut[T]` 構文を置き換え、標準ライブラリで `Slice/SliceMut` 型だけを提供する。その意味論は、rust で `[T]` を借用ポインタと必ず一緒に使うよう強制することに相当する。Zinc の `Slice<'a, T>` は Rust の `&'a [T]` に等しい。

> **TODO**：Range 型は当面未実装だが、演算子は予約済みで、Swift の構文を採用する。Range は二種類あり、開区間 `..<` と閉区間 `..=` であり、`RangeFull` は廃止する。
スライス操作は当面、インデックス演算子 `[]` と Range 型の組み合わせでは実装できない。演算子オーバーロードがまだ実装されていないからである。
```
let s: Slice<Int> = &x[1..<3]; // 今後サポートする
```

## 文字列

文字列は二種類の型に分かれ、`Str` と `String` である。

`Str` は標準ライブラリで定義されたライフタイム付き構造体 `struct Str<'a>` である。`String` 型は標準ライブラリで定義され、`Vec<UInt8>` 型に基づいて実装された、ライフタイムを持たない構造体である。

文字列リテラルは `Str<'static>` 型である。

注：配列スライスと同様に、rust の `str` キーワードを使わないのは、型システムと実装難度を簡略化したいからである。
rust では `str` は合法な型であり、独立して使え、かつ dyn sized である。これは型システムに一種の特例をもたらし、ジェネリクスを実装するときに非常に面倒である。zinc はユーザが `&str` 型だけを使えるようにし、単独の dyn sized な `str` 型もなく、`Box<str>` `Rc<str>` などの型もないようにしたい。
したがって `str` キーワードを置き換え、標準ライブラリで `Str` 型だけを提供する。その意味論は、rust で `str` を読み取り専用借用ポインタと必ず一緒に使うよう強制することに相当する。Zinc の `Str<'a>` は Rust の `&'a str` に等しい。

文字列内部は utf8 符号化である。

C++ の考え方で理解すると、zinc の `String` は C++ の `std::string` に対応し、ただし内部実装は copy-on-write 機構を使う。zinc の `Str` は C++ の `std::string_view` に対応し、コンパイル時ライフタイム検査が追加されている。

文字列リテラルはエスケープをサポートする。

todo: raw string literal をサポートする。`r##" content "##`。

todo: 文字列補間 string interpolation をサポートする。すなわち文字列リテラル内部で入れ子の式をサポートする。例：

```
let name: Str = "Amy";
let s: String = f"hello $(name), how are you?";
```

波括弧ではなく丸括弧を使うのは、zinc では丸括弧が一般に式の場面で使われるからである。式には型と値がある。波括弧は一般に文の場面で使われ、文には型も値もない。

## タプル tuple

0 個の要素を含むタプルを、ユニット型 unit type と呼ぶ。ユニット型は `()` で表す。空タプル `()` 式の型がユニット型である。
関数の戻り型を省略すると、その関数が返すのは `()` 型であることを表す。

1 個の要素を含むタプルは、余分なカンマで終わらなければならず、さもなければコンパイラに「丸括弧式」と判定され、タプルではない。`(1,)` はタプルであり、`(1)` ではない。

2 個以上の要素を含むタプルでは、要素は異なる型であってよい。

## 構造体 struct

`struct` キーワードで構造体を定義する。例は次のとおり：

```rust
struct User {
    active: Bool,
    username: String,
    email: String,
}
```

構造体はジェネリクスをサポートする。
構造体自体と構造体メンバはいずれも pub で修飾できる。
構造体は波括弧内にメンバがなくてもよい。

構造体のメンバはデフォルト値をサポートし、デフォルト値は定数式でなければならない。
```rust
struct User {
    active: Bool = true, // デフォルト値
    username: String = f"",
    email: String = f"",
}
```

構造体初期化式は、C 言語に似ている：

```rust
let user: User = {  // 変数束縛の型を注釈することで、構造体初期化式の型を指定する
    .active = false,
    .username = "John".to_string(),
    .email = "john@gmail.com".to_string(),
};
// あるいは
let user = {  // 型接尾辞によって、構造体初期化式の型を指定する
    .active = false,
    .username = "John".to_string(),
    .email = "john@gmail.com".to_string(),
} : User;
```

構造体は、C 言語のようなメンバの順序による匿名初期化をサポートしない:
```
let user: User = { false, "John".to_string(), "john@gmail.com".to_string() };  // 誤り
```

デフォルト値を持つメンバは、明示的に初期化しなくてもよい。

他の構造体で別の構造体を初期化することをサポートする。ここで使うのは三点 `...` であり、rust の二点 `..` ではない。
zinc では、省略記号を表すのに一律三点 `...` を使う。省略記号構文はいくつかの場面で使われる。省略記号の後ろに式を付けても付けなくてもよい。

```rust
// active は書かなくてよく、デフォルト値を使うことを表す
let user1: User = { .username = "smith".to_string(), .email = String::new() };

// user1 を使って user2 を初期化する。変化があるのは active というメンバの値だけである
let user2: User = { .active = true, ...user1 }; 

// User 型定義中のデフォルト値で user3 を初期化する。変化があるのは active というメンバの値だけである
let user3: User = { .active = true, ... }; 

// これは User 型定義時のデフォルト値ですべて初期化することに相当する。
// 省略記号が必要である。さもなければ字句解析が空の構造体初期化と空の文ブロックを区別できない
let user4: User = { ... }; 
```

構造体は継承をサポートしない。zinc は trait 継承と `reuse` 機構によってオブジェクト指向プログラミングパラダイムをサポートする予定である。

zinc は tuple struct、すなわちメンバ変数に名前がない構造体をサポートする予定はない。単純な構造体については、対応する snake_case 命名のグローバル関数を「コンストラクタ」として単独で提供することを勧める。
こうすると言語規則が比較的簡潔で統一され、使用の観点から見ても命名規則が比較的統一される。大文字で始まる「関数に似た」ものが現れない。
たとえば：

```rust
struct Weight {
    w: UInt32
}

fn weight(w: UInt32) -> Weight {
    return { .w = w };
}

fn main() {
    // 定義側は少し面倒だが、使用側は基本的に tuple struct と区別がない
    let w = weight(1); 
}
```

zinc は「ユニット構造体」をサポートする。メンバ変数のない構造体は、セミコロンで終わってもよく、波括弧内部が空でもよい：
```rust
// 次の二通りの書き方は同じである
struct Unit{} 
struct Unit;
```
ただし注意してほしい。ユニット構造体の初期化は、依然として波括弧が必要である：
```
let x: Unit = { ... };
```

## 列挙体 enum

列挙体は `enum` キーワードで定義する：

```rust
enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let k: IpAddrKind = IpAddrKind::V4;
}
```

列挙体のメンバは関連値をサポートする。
```rust
enum IpAddr {
    V4(Byte, Byte, Byte, Byte),
    V6(String),
}
```

波括弧による関連値はサポートしない。ユーザが引数の命名が必要なら、すべての引数を構造体で包むことを勧める。効果は同じである：

```rust
enum E {
    A{ x:Byte, y: String } // 誤り
}
// 代替の書き方:
struct EA {
    x: Byte,
    y: String,
}
enum E {
    A(EA),
}
```

列挙体メンバのオーバーロードをサポートし、規則は関数オーバーロードと同じで、異なる引数個数のオーバーロードだけをサポートする。

```rust
enum Arg {
    Integer(UInt),
    Integer(UInt, UInt),
    Integer(UInt, UInt, UInt),
    Float(F64),
    Float(F64, F64),
    Float(F64, F64, F64),
}
```

列挙は本質的にタグ付き共用体（tagged union）である。ユーザ定義の enum に、tag がどの整数型か、および各メンバに対応するタグの値を指定することを許す。
タグ値は定数式でなければならず、値は対応する整数で表現できなければならず、各メンバに対応するタグ値は重複できない。

関連値を持たない enum だけが tag の値を指定できる。

```rust
enum IpAddr : UInt8 {
    V4 = 1,  //
    V6 = 2,
}
```

関連値を持たない enum は、`as` 演算子によって整数と直接型変換できる。

列挙型定義はジェネリクスをサポートする。列挙のメンバは新しいジェネリクスを導入できない。

> **計画中の機能**：非網羅的列挙（non-exhaustive enum）の定義をサポートする。構文は最後のメンバの後ろに省略記号を使うことである：
```rust
enum Puctuation {
    Comma,
    Dot,
    Semi,
    ...  // 省略記号。Rust で #[non_exhaustive] によって enum を修飾することに相当する
}
```

## 共用体 union

共用体はキーワード `union` で定義する。共用体全体の大きさは、最大のメンバの大きさに依存する。

```
union U {
    data1: Byte,
    data2: UInt,
}
```

union 型は安全でなく、union 型のメンバの読み書きは、いずれも unsafe コンテキスト中で行う必要がある。

union の初期化構文は struct 初期化構文に似ている。ただしメンバのうち一つだけを選んで初期化しなければならない。

non-trivial 型は、union 型のメンバ変数として使えない。
non-trivial 型には次が含まれる：
1. デストラクタを持つ型。たとえば Arc/Weak など
2. ライフタイム引数を持つ型。たとえば &/&mut など
3. struct のメンバ変数に non-trivial 型があれば、その struct は non-trivial である
4. enum の関連値に non-trivial 型があれば、その enum は non-trivial である
5. 配列型の要素が non-trivial 型であれば、その配列は non-trivial である
6. tuple 型の要素に non-trivial 型が含まれていれば、その tuple は non-trivial である

union 型定義はジェネリック引数を持てない。

union の主な使用場面は二通りある：
1. C とやり取りする場面
2. ビット単位の型変換の場面（rust の `std::mem::transmute` に似る）

たとえば、`F32` 型からビット単位で `UInt32` 型へ変換したいなら、union の助けで完了できる：
```rust
union FloatOrInt {
    f: F32,
    i: UInt32,
}

fn bit_cast_f32_to_uint32(f: F32) -> UInt32 {
    let u: FloatOrInt = { .f = f };
    return unsafe(u.i);
}
```

## 型の大きさ

型は Sized と UnSized に分かれる。Sized 型は局所変数、グローバル変数、メンバ変数として使えるが、UnSized 型は使えず、ポインタを通して間接的にアクセスするしかない。

UnSized 型には次が含まれる：
1. `extern type` で宣言した型
    * `extern type` は主に相互運用場面で使う。その意味は、ある型の定義が他の言語にあり、zinc ではその型の定義を取れない、と宣言することである。したがってその大きさもわからず、メンバ変数に直接アクセスできない。

2. すべての trait
    * `trait R` を定義したと仮定すると、変数の型を `R` と宣言することはできないが、`&R / &mut R / *R` などにはできる

3. 明示的に `impl UnSized for S {}` したカスタム型 `S`
    * `UnSized` は組み込み trait であり、ユーザがカスタム型も Unsized であると指定できる。方式は `impl UnSized for MyType {}` である。
        こうする目的は、この型を「値意味論型」として使うことを禁止し、ポインタで指して使うことだけを許し、この型は「参照意味論型」だけを必要とすることである。
        典型的な場面の一つが、標準ライブラリ中の `File` 型である。この型はユーザが「値意味論型」の仕方で使うことを許さず、ユーザは `File` を指すポインタ型だけを得られる。

ジェネリクスの場面では、現在 UnSized 型をジェネリック実引数として使うことを許さない。
